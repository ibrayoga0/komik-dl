# Purpose

Define a consistent structure for every rule document.

Every rule file should be concise, readable, and easy to maintain.

Use the same section layout across the entire project.

---

# Rules

Use only the approved section headings.

Keep headings short.

Keep wording direct.

Avoid decorative formatting.

Avoid unnecessary nesting.

Avoid excessive blank lines.

Avoid duplicated information.

Avoid AI-style emphasis.

Prefer plain Markdown.

---

# Approved Sections

Use only these section headings when applicable.

# Purpose

Describe the objective of the rule.

# Rules

List mandatory requirements.

# Process

Describe the expected workflow.

# Constraints

Describe prohibited actions.

# Exceptions

Describe valid exceptions.

# Validation

Describe how compliance is verified.

# Notes

Provide optional implementation details.

---

# Formatting

Use Markdown only.

Use ATX headings (#).

Use sentence case.

Use short paragraphs.

Use unordered lists only when necessary.

Keep indentation consistent.

Keep spacing consistent.

Do not use tables unless they improve clarity.

---

# Naming

Use lowercase file names.

Use kebab-case.

Examples:

context.md

workflow.md

security.md

performance.md

editing.md

terminal.md

file-analysis.md

rule-structure.md

---

# Style

Prefer concise language.

Prefer active voice.

Prefer imperative statements.

Write one instruction per sentence.

Avoid redundant wording.

Avoid motivational language.

Avoid conversational language.

Avoid filler text.

Avoid repetition.

---

# Prohibited Formatting

Do not use emojis.

Do not use decorative separators.

Do not use repeated punctuation.

Do not use excessive capitalization.

Do not use bold for entire paragraphs.

Do not use italic for emphasis.

Do not use HTML.

Do not use blockquotes unless quoting documentation.

Do not use code blocks for normal instructions.

---

# Validation

Every rule document should:

Have a clear purpose.

Contain only relevant sections.

Remain concise.

Avoid duplication.

Be understandable without additional context.

Be consistent with every other rule document.

---

# Notes

Not every rule file requires every section.

Include only the sections that improve clarity.

Keep documents simple.

Clarity is preferred over completeness.
